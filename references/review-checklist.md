# 快速自查，以及审一个已有界面

> 文档类型：检查清单和做法。适用范围：用 path-ui 做完东西后的自查，以及按 Path 的思路审一个别人做的、已经在跑的界面。核对基线：2026-11-18，对照 [essence.md](essence.md) 的十四条规则、`scripts/` 下的三个检查工具。
> 清单的格式（每次都过一遍的短清单 + 按影响排序的问题写法）借自 `vendor-skills/apple-design` 的 review-checklist（MIT），条目是按 path-ui 自己的规则重写的。

## 1. 快速自查（每次交付前，15 条都过）

每条后面是对应的规则，和能量它的工具。量得出来的就量，不靠看。

1. **界面上没有 Path 的名字和素材。** 标题、说明、按钮、读屏文字都算（底线；`check_prototype.py`）。
2. **底是中性的。** 颜色只给三样：最核心的入口、内容类型、最多一个状态（规则 11）。
3. **每类内容一个色相、一个字形**，从入口到列表、筛选、加载一路一样（规则 5、12、13）。
4. **彩底上的字和字形够对比度**：字 4.5:1，字形和图形 3:1（`contrast.py --on 底色`，用了 kit 的颜色就 `contrast.py --kit`）。
5. **热闹只给一处**，每个状态变化都选好了级（规则 4、动作分五级）。
6. **东西从叫出它的地方来、回那里去**；反过来的操作倒着放（规则 1、2）。
7. **打开到一半就关不跳**：开和关都量，`startJump` 为 0（`motion-probe.js`）。
8. **平时是静的**：没有为了好看的循环动画（规则 6；`check_prototype.py` 的 loop）。
9. **按下立刻有反应，松手才执行**；焦点看得见；选中不只靠颜色；不能用的写原因；「正在处理」在控件自己身上（规则 14）。
10. **点击区实测不小于 44px**，包括 `::before` 撑大的部分（`PathProbe.hitAreas()`）。
11. **小事就地完成**：能撤销就不弹确认，结果出现在触发它的控件旁边，不弹全局提示（规则 7）。
12. **时间和可见范围交代了**，假数据的时间相对现在生成（规则 8；`check_prototype.py` 的 fixed-dates）。
13. **等待、空、出错、到底都设计了**；加载晚 400ms 露面、露面了留够 500ms、不卡住（规则 10）。
14. **减少动态效果下**：不移动、不缩放、不转，换成淡入淡出或直接到位，状态反馈照样有；Esc、方向键能用（底线）。
15. **说的都做到了**：交付说明里的每一项代码里都有；照搬 Path 的、按规则推的、自己定的分开写（SKILL.md 第 7 步）。

## 2. 审一个已有界面

审的结果是一份按影响排好的问题清单，不是改好的代码。用户点头以后再改，改的做法见 [existing-ui.md](existing-ui.md)。

### 先问清三件事

- **审给谁**：自己接着改，还是交给别人。交给别人的，每条都要写到能照着做。
- **范围**：一个控件、一页、一个流程，还是整站。
- **对照什么**：
  - Path 原样：只有复刻类的界面才这样审。
  - 按 Path 的思路：用十四条规则审。
  - 项目已经有自己的设计系统：视觉以项目的规范为准，只审动效、交互、状态、对比度、点击区这些通用的，再看哪里可以用上 Path 的规则。

### 怎么看

1. **用真的界面。** 能跑真实环境就别只看截图或演示数据：演示数据会藏起空状态、长文字和慢网络。
2. **截整页。** 浅色、深色、手机宽度各一张，先看层次和颜色，再看细节。
3. **每个状态走一遍**：打开、关闭、打开到一半就关、按下又拖开、成功、失败、空、加载、减少动态效果、只用键盘。
4. **量**：
   - 动效用 `motion-probe.js` 的 `scrub` / `peaks`；
   - 点击区用 `hitAreas()`；
   - 对比度用 `contrast.py`；
   - 单文件原型再跑一遍 `check_prototype.py`。

### 问题怎么写

每条一行到三行，四个部分：

- **哪里**：页面和元素，最好附截图位置。
- **现在怎样**：带证据。截图、量到的数字（「点击区 32×28」「白字在黄底上 1.4:1」「关到一半先跳回原位 145px」）。
- **为什么是问题**：用白话说清违反了什么（「用户点了右上角的铃铛，提示却从左下角滑出来，看不出是谁叫出来的」）。规则编号是给自己查的，不写给用户。
- **怎么改**：具体到零件和参数（「改成 `growFrom(panel, bell)`」「夏黄底改用深色字 #1F1A16」）。

### 怎么排

按影响排，不按发现的先后：

1. 用不了、看不清：点不到、对比度不够、键盘走不通、状态看不出来。
2. 看不懂：层次乱、东西不知道从哪来、同一类事几种动作、颜色没有意思。
3. 节奏和细节：动效太长或太花、平时在动、等待一闪而过。

最后单列「做得好的、要保留的」，改的时候别动它们。
