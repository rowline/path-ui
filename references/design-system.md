# 用 Path 的思路做全套 UI：设计系统补全规范

> 文档类型：设计系统扩展规范。适用范围：用 path-ui 做整站 UI（按钮、表单、列表、导航、深色模式、桌面宽屏），以及接进已有设计系统时听谁的。核对基线：2026-11-26，对照 [essence.md](essence.md) 和 [path-kit.css](../assets/path-kit/path-kit.css)。

`path-kit` 覆盖了时间线、发布菜单、滚动时钟、情绪回应、掉落弹窗等 8 组特色交互，但一个产品里大部分是按钮、表单、列表、导航和多屏布局。这份规范补上这部分的默认做法，免得「特色组件像 Path，其余页面退回普通后台模板」。

**先说清楚两件事：**

- **这里的取值大多是自定的。** Path 是手机 App，没有设置页、表格、桌面多栏，也没有深色模式，没有原版可量。按 [essence.md](essence.md) 的规则推出来的地方标了规则号；标「自定」的是建议值，交付时归到「你自己定的」那一类。
- **已经有设计系统的项目，视觉和取值不在这里定。** 以项目自己的规范为准。本文件第 2–5 节的取值只给新项目用；对已有设计系统的项目，只说动效怎么分级、kit 怎么接（见 [porting.md](porting.md) 最后一节）。

---

## 1. 两套落地方案（先选一种）

| 场景 | 样式入口 | 视觉听谁的 | 默认强度 |
| --- | --- | --- | --- |
| **独立项目 / 新产品** | `path-kit.css`（加 `data-pk-skin="p4"`；深色加 `data-pk-theme="dark"` 或 `"auto"`） | 本文件第 2–5 节 | 工具 / 办公 `0.3–0.5`；生活 / 日记 `0.7–1` |
| **已有设计系统的项目** | 项目样式 → `path-kit.css` → 自己写的桥接表（把 `--pk-*` 指到项目变量，见 porting.md 最后一节） | 项目自己的规范；本文件第 2–5 节的取值不适用 | 默认 `setIntensity(0.4)` |

## 2. 颜色、表面和深色模式（独立项目）

### 2.1 三层表面（自定）

1. **桌面衬底（`--pk-desk`）**：窗口最底层。桌面端侧边导航直接坐在这一层上，不另加背景块。
2. **主纸面（`--pk-paper`）**：正文所在的一整张面。宽屏时四周留边、带大圆角和极淡的边影；手机上铺满窗口，省掉桌面层。
3. **纸上淡底和浮层（`--pk-wash` / `--pk-card`）**：同一张纸里分右栏、选中行、输入底时用 `--pk-wash`，不用硬边框堆卡片；只有弹窗、下拉浮层、引导卡用 `--pk-card` 浮起来。

### 2.2 深色模式

`path-kit.css` 支持 `[data-pk-theme="dark"]`、`[data-pk-theme="auto"]`（跟随系统）和 `.dark` 下的 `.pk-root`，两代皮肤都能切。深色的值全是自定的。改深色时注意：

- **不用纯黑**：底面用低饱和的暖炭色（`#171513`），留出层次差。
- **影子换亮边**：深色下投影看不清，浮层改用 1px 极淡的亮边区分层级（`--pk-shadow-float`）。
- **压印**：浅纸靠「微暗凹槽 + 下沿白高光」；深纸改成「更深的暗槽（`rgba(0,0,0,.48–.52)`）+ 极淡的下沿微亮（`rgba(255,255,255,.08–.11)`）」。不要直接套浅色的 `rgba(255,255,255,.85)` 白边，会发亮刺眼。
- **弹窗压暗（`scrim`）**：浅色工具页面 `0.35–0.45`；深色页面可以到 `0.55–0.65`，免得卡片和背景糊成一片。
- **状态和种类色**：浅底上用高饱和图标配浅色底块；深底上把底块换成同色相的低明度深色，正文保持高对比度。

### 2.3 类型色、状态色和字形

按 [essence.md](essence.md) 规则 11–13 来，这几条是从 Path 的录屏里量出来的，不是自定：

- 每种内容类型一个色相、一个字形，入口、列表、筛选、加载里都一样。kit 的 `--pk-type-*` 和 `glyphSvg` 是现成的。
- 状态色最多一个。Path 只给「私密」上色（`--pk-private`），其他状态用字说。
- 白字形放在浅色底上不够对比度时，开 `data-pk-contrast="more"`，或者改用深色字。

## 3. 字体、排版和圆角（独立项目）

### 3.1 字体

- 字体栈：`-apple-system, "PingFang SC", "Noto Sans SC", "Source Han Sans SC", "Microsoft YaHei", sans-serif`。
- 时间、计数、金额、耗时一律 `font-variant-numeric: tabular-nums`，数字对齐。

### 3.2 字号和字重

| 用途 | 建议 | 依据 |
| --- | --- | --- |
| 正文 | 14–15px，行高 1.5–1.6，400 | 自定 |
| 人名、地名、时钟钟点 | 加粗 700 | Path 时间线（essence 模式 2：粗体是人名和地名）；kit 的时钟钟点是 13px / 700 |
| 情境、时间、来源 | 11–12px，灰字 `--pk-ink-2` | Path 时间线下面的灰色小字 |
| 弹窗、引导标题 | 17–20px，600–700 | 自定 |
| 按钮、表头、表单标签 | 13–14px，500 | 自定 |

手机上的输入框字号至少 16px，免得 iOS 聚焦时放大页面。已有设计系统的项目用它自己的字号表。

### 3.3 圆角

| 对象 | 独立项目 | 来源 |
| --- | --- | --- |
| 主纸面（桌面端） | 16px | 自定 |
| 卡片、弹窗 | `--pk-radius`：10px（Path 2 皮肤 6px） | kit 默认 |
| 回应浮层 | `--pk-radius-pop`：10px（两代一样） | kit 默认 |
| 按钮、输入框 | `--pk-radius-btn`：8px（Path 2 皮肤 6px） | 自定 |
| 胶囊标签、开关、状态点 | `--pk-radius-pill`：9999px | 自定 |

已有设计系统的项目，在桥接表里把 `--pk-radius*` 指到项目的圆角变量。

## 4. 基础控件（独立项目的默认做法）

所有基础控件都按 [essence.md](essence.md) 的规则 4、6、7、14 来：**热闹只给一处、平时是静的、小事就地完成、按下就有反应**。

### 4.1 按钮

| 类型 | 视觉 | 动效 |
| --- | --- | --- |
| 主按钮 | 实心 `--pk-brand` + `--pk-on-brand` | 一屏或一个区域最多一个（规则 4）。按下只微缩（`scale(0.98)`，≤ 100ms）或变色，不加 `pop` 回弹 |
| 次要 / 描边 | 纸底 + `1px solid var(--pk-rule-strong)` | 平等的选项（「周六 / 周日」「取消 / 修改」）同级并列，不把其中一个涂黑 |
| 幽灵 / 行内 | 透明底，悬停浮出 `--pk-wash` | 列表行内的小动作、筛选、关闭。视觉高度自定（桌面 24–28px，手机 32–36px），点击区至少 44px |
| 危险 | 浅红底 + 红字，不整块大红 | 不可逆的删除先确认：独立项目用全站唯一的 `dropModal`（`role: 'alertdialog'`，规则 5） |
| 状态切换（星标、收藏、完成） | — | `pop(el, { from: 1 })` 或 `popToggle`（第 3 级） |

- **响应式按钮高度不锁死覆盖**：用 CSS 变量承载默认按钮尺寸（随 `@media` 切换桌面与手机取值），不要在基础变体里写死带断点前缀的高度类（如 `sm:h-7`），以免覆盖卡片或多行选项按钮的自定高度。

### 4.2 表单和就地编辑

- **结构**：框外标签 → 输入区 → 简短说明 → 校验错误。不拿 placeholder 当标签。
- **高度**：输入框桌面 32–36px、手机 40–44px（自定）。
- **聚焦环**：统一的 `outline` 或细环，出现时布局不跳。
- **通用下拉与日期/时间选择器**：不要在表单或弹窗里保留系统原生 `<select>` 与 `<input type="date|time|datetime-local">`（容易出现默认蓝框、尺寸/语言割裂）。统一封装共享选择器和日期/时间弹层：
  - 展开使用 `growFrom(panel, trigger)`、收起用 `shrinkTo`、箭头用 `turnTo`、选项点选用原地 `pop` 与中性高亮底（不使用青色品牌底）。
  - 若触发器位于原生 `<dialog>` 内，弹层挂载到 `trigger.closest('dialog')` 以留在 Top Layer；按 `Esc` 先收起选择器并返回触发器焦点，不关闭外层对话框。
  - 桌面触发器高度、圆角与普通输入框对齐；`<640px` 移动端触发器与选项高度不少于 `44px`，输入/触发字号不低于 `16px`。
- **就地生效（规则 7）**：开关、单选筛选、行内勾选在原地生效。保存中在行内显示状态，不要每拨一个开关就在页面顶上弹「保存成功」；失败时回到原值，就地给出重试。
- **提示与修复动作就地归组**：状态提示或校验说明与其直接操作按钮（「重新检测」「重试」）放入同一反馈容器或保持 `8–12px` 组内间距、与下一表单项隔开 `16–24px`，避免 CSS 重置或失效选择器造成提示卡与按钮 `0px` 贴死。
- **异步提交**：提交后按钮切成「正在……」。结果条目直接落进当前列表时，用 `flyFrom(newRow, submitBtn)` 从按钮飞进去（规则 1）。

### 4.3 列表、设置行和表格

- **分隔线**：行间 `1px solid var(--pk-rule)`。选中行整块填 `--pk-wash`、加一圈 `--pk-rule` 边，同时隐去它上下的分隔线。
- **只说一次、只标例外**：每行都一样的字（「页内」「在线」）提到表头或省掉；正常状态不占字不占色，只有「离线 / 失败 / 等待中」才给小色块或图标。
- **高密度网格与月历单格上限**：月历单元格、日程矩阵等固定节奏网格，桌面与移动端均必须限定单格可见条目上限（例如桌面最多 3 槽，超过 3 条时显示前 2 条与「还有 N 项」；手机最多 3 点与 `+N`），防止单日数十条记录把整行网格撑成长条；完整列表交由可滚动预览栏或二级详情页展示。
- **多分区页内列表默认上限（≤ 5 条）**：同一页承载多个内容区块（如状态卡 + 声音片段 + 识别记录）或非专属全屏档案页的记录流时，每个列表块默认最多展示 **5 条**（切换筛选后重置为前 5 条）；超出条数收敛到底部就地展开条（「展开其余 N 条 / 收起，只看前 5 条」，点击区 ≥ 44px），由用户按需展开并随整页自然滚动，避免首块几十条记录把后续区块顶出屏幕，也不做固定高度框中框滚动。
- **行的增删**：
  - 新增：`flyFrom(row, 触发按钮)`（规则 1）。
  - 归档 / 删除：`flyTo(row, 目的地)` 飞向「已归档」或回收站，那里的计数接着 `pop(countEl, { from: 1 })` 鼓一下。
  - 旁边的行让位：`fly(el, { from: [0, dy], to: [0, 0], ms: 250, easing: motion.ease.out, fill: 'none' })`，不冲过头（让位的不是主角）。
- **长列表和虚拟滚动**：
  - `timeScroller` 靠容器里带 `data-time` 的真实节点。分页追加以后要调 `scroller.refresh()`。
  - 用虚拟滚动（节点会被回收）时，要保证时间锚点还在，或者改用数据索引算当前时间，别让滚动时钟突然跳空或闪一下。

### 4.4 导航和选项卡

- **平时是静的（规则 6）**：侧边栏、顶栏、Tab 栏本身不做悬停弹跳或呼吸灯。
- **切 Tab**：内容区用 `fadeIn(panel, { ms: 160 })`（第 4 级），不要整页 `dropIn` 或大幅横滑。
- **位置只说一次**：桌面端左栏的高亮已经说明了当前在哪，右边页面顶上不再放一个大标题重复一遍。

### 4.5 弹窗尺寸和扇形菜单的另一种展开方式

- **弹窗尺寸（独立项目的 `dropModal`）**：
  - 确认、短提示（`alertdialog`）：默认 `--pk-modal-max: 340px`。
  - 桌面表单、详情编辑（`dialog`）：在 host 上设 `--pk-modal-max: 460px`（自定）。双列表单也别超过 520px；再大就该用右栏或独立页面，不用会晃的掉落弹窗。
  - 桌面工具页的摆动幅度用 `setIntensity(0.4)`（约 -1.6° → +1.2° → -0.4°）：有重量，不轻浮。
  - 项目已经有对话框组件时，继续用它，不引入第二套实现。想要掉落 / 摔出的手感，就给现有对话框的内容加 `dropIn` / `fallOut`。
  - **弹窗与主页面控件保持同源**：弹窗或旧向导模块中的输入框、下拉选择器与按钮须共用全站统一圆角、触控尺寸与明暗变量，不能留下一套 8px/旧配色的孤立样式。
- **扇形菜单的另一种展开方式**：
  - 扇形弹出菜单有专利 US9448692B1（见 SKILL.md 底线）。商用产品要用，先请法务评估。
  - 法务建议换一种展开方式，或者产品本来就不想要扇形时，可以这样做：
    1. 触发按钮原地 `turnTo`（或切成选中态）。
    2. 紧贴按钮用 `growFrom(panel, 按钮)` 长出一块圆角动作面板（单列或紧凑网格，每项带类型图标和中文标签）。
    3. 面板里的各项错开约 20ms `fadeIn`（强度 0.4）。选中的那项 `pop` 一下，面板 `shrinkTo` 收回按钮。
  - 这样保留了「从哪来回哪去、一类符号贯穿、短而跟手」的手感，外观上也离原版更远。但这不等于不侵权：专利写的是「从菜单图标沿路径弹出多个子图标」，覆盖到哪里由法务判断。交付时照样写专利提醒，不要写「已避开专利」。

### 4.6 列表到二级详情的连续性与长文本详情阅读

1. **列表到同域二级详情保持容器与顶部连续**：
   - 从列表点进同域二级详情（如相册、录音、录像详情）时，应复用同一内容限宽基准与工具栏起点；禁止列表 `960px`、详情突然跳成全宽，也不得在返回按钮上方另留一层多余的空带或给列表子组件叠额外水平 `padding`。
   - 返回动作（如 `‹ 录音`）放在独立工具栏左侧，与列表顶栏同一起点。
2. **标题、面包屑与正文不三连复读**：
   - 机器文件名（UUID、时间戳编号、`IMG_` 前缀等）只留作技术档案与导出兜底，禁止放进主标题、面包屑或引用名。
   - 当无人工标题而由摘要或正文回退生成标题时，只取**首行第一句**并去掉末尾多余句号（保留问号/感叹号）；顶栏面包屑末项限制单行最大宽度（如 `max-width: 22rem`）并保留悬停完整提示，避免一段长文在面包屑、H2、摘要卡里复读三遍。
3. **长文本 / 音视频详情布局**：
   - **吸顶主控 + 非对称主次双栏**：桌面端采用「宽主阅读列 + 窄吸顶信息栏（约 `300px–340px`）」，播放条/核心控制栏在滚读时吸顶常驻（层级低于顶栏）；禁用 `50/50` 均分，免得摘要侧空着一大截、长文侧行宽过窄。
   - **自然页面流，禁框中框固定高度滚动**：不要给正文容器设 `max-height` 配 `overflow: auto` 与整页滚动打架；超过折叠阈值（如 800 字或 15 句）时默认折叠为前段预览配柔和渐隐，展开后随整页自然滚动，并提供「收起全文」与「回到顶部」。
   - **按长度与结构条件增强**：较长正文（如 > 500 字或 10 句）才出现轻量文内检索与高亮；多说话人时展示筛选芯片；无断行的纯文本在渲染层按语义断句视觉分段（复制与下载导出保留原文）。
   - **高危动作显式隔离、空标注不占位**：删除/删掉等破坏性按钮统一危险态（红字/淡红底或红框），留出安全间距并先确认再执行；未填写的可选标注不逐行渲染「还没填…」空占位。
   - **媒体深链接与同向翻页**：重信息媒体详情提供独立可书签路线而非仅临时弹窗；底部胶片条缩略图顺序必须与序号和左右翻页方向严格一致。

## 5. 多页面的主角分配和全局反馈

### 5.1 每一页只有一个主角（规则 4）

全站用 Path 的思路，不等于每一页都要有第 1 级动效：

| 页面类型 | 第 1 级主角（唯一的热闹处） | 最高用到 | 不要 |
| --- | --- | --- | --- |
| 日记 / 动态时间线 | 发布入口（加号） | 1–4 级 | 每条动态卡片自己带复杂弹出 |
| 列表 / 检索 / 档案 | 主筛选或主新建入口（只用颜色强调，不动） | 第 3 级（星标、归档飞入、计数 `pop`）+ 第 2 级（删除确认） | 在列表页再放一个大红扇形加号 |
| 设置 / 表单页 | 没有第 1 级；主保存按钮在表单底部 | 第 3 级（开关、新增项落位）+ 第 4 级（行内展开 `growFrom`） | 一打开页面，卡片就一张张飞进来 |
| 仪表盘 / 监控页 | 异常告警块（静态高亮底，不闪） | 平时第 5 级（全静）；只在正在执行时显示压印加载 | 呼吸灯、数字一直滚动跳动 |

已有设计系统的项目里哪一处当主角，按项目自己的定位和用户点头的样稿来，这张表不替它定。

### 5.2 没有锚点按钮的全局反馈

1. **有全局状态条的产品**：后台任务完成、断线、待决策，优先收进状态条，不出漂浮的提示。
2. **没有全局状态条的独立产品**：只在「没有固定触发控件的异步结果」（连接断开、后台导出完成）时，在右上角或底栏上方出一条轻提示：
   - 出现：`fadeIn(toast, { from: [0, 8], ms: 180 })`（第 4 级）；消失：`fadeOut(toast, { ms: 200 })`。
   - 同屏最多一条，带关闭按钮，鼠标悬停或聚焦时暂停自动消失。

## 6. 多文件工程的验收补充

[check_prototype.py](../scripts/check_prototype.py) 只检查**单文件 HTML 原型**。在 React / Vite 等多文件项目里落地时，补这四项：

1. **不露品牌**：全局搜一遍，用户看得到的文案、`title`、`aria-label`、`alt`、`placeholder` 里没有 `Path` 字样，也没有引用原图。
2. **两种主题的对比度**：浅色、深色各截一次屏，查 `.pk-deboss`、`.pk-clock`、`.pk-react`、`.pk-drop-card` 和背景的对比度。两代皮肤都要切到深色看一眼。项目有自己的对比度测试就一起跑。
3. **打断和减少动效**：在无头浏览器里测「打开到一半马上关」「动画中卸载组件」，不报错、不跳帧；`emulateMedia({ reducedMotion: 'reduce' })` 以后 `getIntensity() === 0`，不转、不大幅弹跳。
4. **键盘和点击区**：`dropModal`、`radialMenu`（或它的替代面板）、`reactionPicker` 都能用 Esc 关闭，焦点回到触发按钮；390px 宽时所有能点的控件高度或点击区不小于 44px，没有横向滚动。
